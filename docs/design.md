# アブダクション語学学習 Webアプリ 設計案 v4（ファンメイド・非公式）

## 0. 前提
- 元ネタ: 今井むつみ『アブダクション英語学習法』（第2部レッスン0〜7＋おわりに まで確認済み）。非公式ファンメイド
- GitHub Pages（静的）／無料／メールOTPログインのみ
- 本文・例文・登場人物は転載・流用しない。使うのは手順の構造と13動詞のリストだけ
- 母語(L1)と学習言語(L2)は自由に選べる。英語×日本語はその一例
- 読み上げは Web Speech API（ブラウザ内蔵、トークン消費ゼロ）

## 1. 本の手順（第2部全体から抽出）

### DDLの3ステップ
1. 例文を出力する
2. 例文を比較・検討して仮説を立てる（アブダクション）
3. 立てた仮説を検証する

### 探究の単位
- 語のペア／グループ（listen & hear、think & believe & know）
- 句（look at）
- 構文パターン（「I think + that節」対「I consider + O + C」）
- 「おわりに」で次の題材として挙がるもの: 前置詞 at/in/on、可算・不可算（a chicken / chicken）、冠詞 the / a、時制
  → 単位は「語・句・パターン」の3種を扱えれば全部カバーできる
- 探究には「問い」が付くことがある（「I think の代わりになる動詞は？」）。ペアの違いを探るのとは動機が違う

### STEP 1 例文出力
- 各対象10個、L1訳つき、対象を太字。「こちらが頼むまで解説しない」が必須
- パラメータ: レベル／ジャンル／語数上限／副詞あり・なし／対比相手（一部だけ出しつつ他の語との違いがわかる副詞を入れる）
- 補助: 目的語・補語に下線（構造の補助線はネタバレではない）
- 前の探究で出した例文セット（think）を新しい探究（consider）で再利用する

### STEP 2 比較・検討
- 着眼点は蓄積: 訳語／修飾する副詞／目的語（動作の対象）／後続の前置詞／構文（文型）／目的語の中身（that節の内容）
- 表の形
  - 語ごとの一覧
  - 共通項目の比較（同じ副詞×語→訳語）
  - 共通／固有の切り分け（その語でしか使われていない副詞）
  - 項目の意味的な分類（動きあり／なし、一般論／願望／事実認識、軽い話題／具体的な意見）
  - 訳語の言い換え可否（「信じている」を「考えている」に替えても意味が変わらないか）
- 母語側の振り返り: 母語ではどう分けているか（漢字の使い分け みる／視る／観る、古語の多義、外来語 トークイベント／リスニング）
- 文型分析（S/V/O/C）は学習者自身が行い、仮説に「意味の違い＋構文の違い」として統合する
- 仮説は版を重ねる。「？」つきの行がある。形は一行・表・包含図（see の中に look / watch）のいずれか
- 過去のスキーマ（意図的／偶発的、目的語をとる／とらない）を新しい対象に持ち込む。外れることも織り込み済み

### STEP 3 推論を確かめる
- 主方式: 仮説を試すL1文を作り、どの語が出るか予想してから、AIにL2訳させる
  - 1文に対象概念が複数回（①②③）、会話形式、極端なケース（サボテン）
  - 候補語を限定して訳させる（「think / believe / know のなかから適切なものを使って」）。限定しないとAIは無難な語に寄る
  - 訳語を固定して差をほかの部分に出させる（「すべて『思う』と訳し、ニュアンスはほかで表現して」）
  - 可否質問（「consider を使って訳せますか？できるなら訳して」）
  - テスト文が意図を表せていなければ書き直して再実行（「思う」→「わかっている」）
- 副方式
  - フレームテスト: 診断的な枠が自然に成り立つか（「I plan to see…」「I happen to see…」「by accident」）
  - 同じ目的語で語を替える対比（see a movie / watch a movie）
  - ジャンルを変えて再出力し、全文が仮説で説明できるか
  - 実在テキスト（歌詞など）で語の選択を仮説で説明する
- AIは求めなくても解説を付けてくることがある。訳と解説は分けて受け取り、解説は畳んでおく
- AIの訳には偏り（believe＝信じる、know＝知っている）がある。学習データの偏りとして理解して付き合う

### 検証後
- AIが隣接語を勧めてくる（stare at / glance at、reconsider / rethink）→ 次の探究候補になる
- 「自分の仕事の場面で使えることば」に接地させる（ジャンルの個人化）
- 「記号接地待ち」: 一度学んでも忘れる。繰り返し出会い、使い続けることで接地する（おわりに）

### 生成AIについて（コラム＋おわりに）
- 文法ミス（are look at）は起こる。「おかしくないですか？」と聞き返して再出力させる。少し不自然な程度は許容
- 生成日時・モデルで結果が変わる
- どの生成AIでもよい。完璧な先生ではなく、上手に使う相棒

## 2. アプリの中核モデル

```
概念グループ（L1の概念: 「話す」「見る」）
  └ 探究（Inquiry） = { L1, L2, 対象[1..4], 問い?, 既定ジャンル }
      対象 = { label, kind: word | phrase | pattern, spec }
      └ カード列（タイムライン。どこからでも追加できる）
          ・例文セット   (STEP1) 新規生成 or 他の探究から取り込み
          ・観察         (STEP2) 着眼点1つにつき1枚
          ・構文分析     (STEP2) 学習者がS/V/O/Cをタグ付け
          ・仮説 v1,v2…  (STEP2) 一行／表／包含図 ＋「？」
          ・検証         (STEP3) 翻訳テスト／フレームテスト／対比／再出力検証／テキスト確認
          ・まとめ・出力
  └ グループまとめカード（複数探究の最終仮説を1表に統合）
```

- 「訳・AIの見解・AIの解説」は学習者の操作で明示的に開く。既定は隠す
- 仮説が0枚のときは検証カードを作れない
- 着眼点ライブラリ: 使った着眼点がユーザー単位で蓄積し、候補として出る
- 気づきノートの過去スキーマを「仮説として持ち込む」ボタン（ブートストラッピング）
- 「次の探究候補」: まとめ時にAIへ隣接語・派生語・関連構文を尋ねられる（学習者が押したときだけ）
- 「再訪」: ホームに過去のスキーマカードを1枚出し、「今日も1文書く」を促す。軽い間隔反復

## 3. 各カードの仕様

### 3-1. 例文セット（STEP 1）
入力: 対象（全部または一部）、個数（既定10）、レベル、ジャンル、語数上限、副詞あり/なし、対比相手
出力（JSON）:
```
{ target, sentences: [{ l2, l1, spans: { target:[..], object?:[..], complement?:[..], adverb?:[..], preposition?:[..] } }],
  meta: { model, generated_at, params } }
```
- 対象をハイライト。訳は各文のトグル。読み上げボタン
- 「補助線」トグルで object / complement / adverb / preposition の下線（既定オフ）
- 他の探究の例文セットを「取り込む」（コピーではなく参照）
- QAパス: 表示前に安価なモデルで文法チェックし、疑わしい文に「？」を自動付与。学習者も手動で付けられる
- 「？」の文は「指摘して再生成」でその文だけ／セット全体を再出力
- 免責表示＋生成日時・モデル名

### 3-2. 観察（STEP 2）
- 着眼点を選ぶ（ライブラリから／新規）: 訳語／修飾語／目的語・対象／目的語の中身／後続の前置詞／主語／文の種類／母語側の分け方／自由
- 学習者が例文中の語をタップしてマーク → 対象ごとの列に集計表
- 各項目に自由な「特徴タグ」（動きあり／なし、一般論／願望／事実、言い換え可／不可…）→ タグ別集計
- ピボット: 共通項目の比較（項目×対象→訳語）、共通／固有の切り分け
- 「母語側の分け方」は例文を使わないメモ型の着眼点（漢字の使い分け、外来語、古語）
- 任意: 「AIにも抽出させて比べる」（学習者がマークした後だけ）
- 言語ごとの着眼点パック（共通: 訳語・修飾語・共起語・文の種類・母語側の分け方。英語: 文型・前置詞・冠詞・可算性。日本語(L2): 助詞・自他動詞。中国語: 補語・アスペクト助詞…）

### 3-3. 構文分析
- 例文を選び、学習者が言語パックの要素（英語: S/V/O/C/前置詞句/that節/to不定詞）をタグ付け
- 対象ごとに「構造パターン集計表」
- 「AIの分析を見る」はタグ付け後に開示

### 3-4. 仮説
- 形式: 一行（対象ごと）／表（対象×観点）／包含図（円の入れ子で「一般」と「特別なケース」）
- 各行に「？」マーク、自由メモ、根拠にした観察カードへのリンク
- 保存で v1, v2, … 差分表示。「この版に戻して分岐」
- 「過去のスキーマを仮説として持ち込む」

### 3-5. 検証（STEP 3）
a. 翻訳テスト（主方式）
   1. L1で文（複数文・会話形式も可）を書く。対象概念の出現箇所を①②③とマークし、各箇所に予想を記録
   2. オプション: 候補語を限定／訳語を固定して差をほかで表現／可否質問（特定の語で訳せるか）
   3. AIがL2訳し、各番号にどの語を使ったかを対応づけて返す
      `{ l2_text, alignments:[{index, word}], note? }`  note は畳んで表示
   4. 番号ごとに一致／不一致。不一致は「驚き」として仮説修正を促す
   5. テスト文を書き直して再実行できる。履歴は残る
b. フレームテスト
   診断的な枠（L1で「〜するつもりだ」「たまたま〜」など）を対象語に当てはめ、成り立つかをAIに尋ねる。学習者の予想を先に記録
c. 対比生成
   同じ目的語・同じ文脈で対象語だけ替えた文を並べる
d. 再出力検証
   ジャンルを変えて例文セットを生成し、各文を「仮説で説明できる／できない」に仕分け
e. テキスト確認
   手元のL2テキストを貼り付け → 対象をハイライト → 各出現を仮説で説明できるかメモ
- どの方式も「AIの見解」は学習者の回答後に開示

### 3-6. まとめ・出力
- 最終仮説を「スキーマカード」として気づきノートへ保存
- グループまとめ: 同じ概念グループの探究の最終仮説を1表に統合
- ライティング: コンセプトを使ってL2で3文書く（自分の仕事や趣味の場面で）→ AIが相棒として根拠つきコメント（判定語は使わない）
- 次の探究候補: 隣接語・派生語・関連構文をAIに尋ね、ワンタップで新しい探究を作る

## 4. AIプロンプト方針
- システム: 学習者が主体／求められるまで意味・文法の解説をしない／訳・補助線・解説は構造化フィールドに分ける／間違えることがあると自覚し確信度を添える／候補語や訳語の指定があれば厳守する
- 生成はすべて JSON 構造化出力。開示タイミングはUIが制御
- L1/L2 はパラメータ。UI言語はL1
- 生成ごとに model と generated_at を保存
- 本体生成は `claude-opus-5`、QAパスは `claude-haiku-4-5`
- 1回の例文生成 ≒ 入力700 + 出力1,000トークン。QAパス ≒ 入力600 + 出力200

## 5. 多言語対応
- L1/L2 は BCP47 コード。組み合わせ自由
- 既定コースは言語ごと。英語: 聞く／話す／見る／考える の13動詞（MVP）。後日: 前置詞、可算・不可算、冠詞、時制（いずれもパターン対象で表現できる）
- Web Speech の音声はOS依存。利用可能な voice を検出し、無い言語は読み上げボタンを非表示。iOS Safari はボタン押下起点でのみ再生

## 6. 技術構成
| 層 | 選択 |
|---|---|
| フロント | Vite + React + TypeScript + i18n。PWA。GitHub Actions → Pages |
| 認証 | Supabase Auth メールOTP（6桁コード） |
| 保存 | IndexedDB（Dexie）主。ログイン時 Supabase Postgres へ同期（RLS） |
| LLM | Supabase Edge Function → Claude API（構造化出力）。JWT検証、1日回数制限 |
| BYOK | 任意で自分のAPIキー（localStorage）。他社プロバイダ対応は将来のアダプタ追加で |
| 例文バンク | 既定コース分は事前生成JSONを同梱。STEP1はオフラインでも動く |

## 7. データモデル
- `concept_group` { id, user_id, l1, l2, label }
- `inquiry` { id, group_id, targets[{label, kind, spec}], question?, genre_default, created_at }
- `card` { id, inquiry_id, kind, parent_card_id, payload(json), created_at }
  - kind: examples | observation | syntax | hypothesis | verify | writing
  - examples の payload に `source_card_id` があれば他探究からの参照
- `perspective` { id, user_id, l2, label, kind }（着眼点ライブラリ）
- `schema_note` { id, user_id, l2, targets[], summary, form, from_hypothesis_id, last_revisited_at }
- `flag` { card_id, sentence_index, source: auto|user, reason }

## 8. 画面
1. ホーム: L1/L2、既定コース、自由入力（語・句・パターン＋問い）、進捗、「再訪」カード
2. 探究画面: 左タイムライン／右「現在の仮説 vN」。スマホは1カラム＋下タブ
3. 観察ワークシート: 例文一覧＋タップでマーク＋集計表（一覧／ピボット／共通・固有／タグ別）
4. 気づきノート: 概念グループごとにスキーマと版履歴、グループまとめ、次の探究候補
5. 設定: ログイン、APIキー、モデル、音声、残り回数

## 9. MVPの範囲（第1段階）
- 英語×日本語で動作確認。L1/L2はコード上は最初からパラメータ
- 対象は語・句・パターンの3種に最初から対応（UIは語から）
- カード: 例文セット（補助線・QA・？付き）、観察（一覧・タグ・共通／固有）、構文分析（手動タグ）、仮説（一行＋？）、翻訳テスト（番号つき予測・候補語限定・可否質問）、フレームテスト、まとめ
- 音声: Web Speech
- ログインなし（ローカル保存）
- 第2段階: OTP・同期、着眼点ライブラリ、グループまとめ、包含図、例文セットの取り込み、次の探究候補、再訪、追加コース（前置詞・可算性・冠詞）
